# CUDA_RUNTIME_PLAN.md — خطة مكوّن تسريع CUDA الذاتي

> هدف واحد: **المستخدم النهائي لا يثبّت أي شيء إطلاقاً**.
> عند تفعيل خيار CUDA في الإعدادات، ينزّل التطبيق مكتبات التشغيل تلقائياً
> (تحقق SHA-256 + تثبيت ذري + تراجع آمن)، ويعمل التسريع على NVIDIA.
> الخطة تشمل الشروط الثلاثة المعتمدة لضمان **صفر أخطاء وقت تشغيل**.

---

## الشرط 1 — قائمة ملفات كاملة (لا cublas/cudart فقط)

ONNX Runtime بمزوّد CUDA يحتاج **cublas + cuDNN** معاً (نماذج MDX-Net تعتمد على
التفافات CNN → cuDNN حاسم). الحزمة `cuda-runtime` في `assets-v1`:

| الملف | الدور | ملاحظة |
|---|---|---|
| `cudart64_12.dll` | CUDA Runtime الأساسي | إلزامي |
| `cublas64_12.dll` | الجبر الخطي (GEMM) | إلزامي |
| `cublasLt64_12.dll` | cublasLt (المسار الأسرع) | إلزامي |
| `cufft64_11.dll` | تحويلات Fourier (تبعية مباشرة لمزود ORT — غيابها كان أول فشل مثبت) | إلزامي |
| `cudnn64_9.dll` | واجهة cuDNN الرئيسية | إلزامي |
| `cudnn_ops64_9.dll` | عمليات cuDNN الأساسية | إلزامي |
| `cudnn_cnn64_9.dll` | نواة الالتفاف CNN | إلزامي (قلب MDX-Net) |
| `cudnn_adv64_9.dll` | عمليات متقدمة | إلزامي |
| `cudnn_graph64_9.dll` | واجهة الرسم البياني (غيابها أسقط التهيئة بانهيار أصلي مثبت) | إلزامي |
| `cudnn_heuristic64_9.dll` | اختيار المحرك الأمثل | إلزامي (ضمن المجموعة الكاملة) |
| `cudnn_engines_precompiled64_9.dll` | محركات مسبقة التجميع | إلزامي (ضمن المجموعة الكاملة) |
| `cudnn_engines_runtime_compiled64_9.dll` | محركات وقت التشغيل | إلزامي (ضمن المجموعة الكاملة) |
| `cudnn_engines_tensor_ir64_9.dll` | محركات Tensor IR | إلزامي (ضمن المجموعة الكاملة) |
| `cudnn_ext64_9.dll` | ملحقات cuDNN | إلزامي (ضمن المجموعة الكاملة) |
| `onnxruntime_providers_shared.dll` | جسر المزودين (مطابقة 1.22.0 الدقيقة) | إلزامي |
| `onnxruntime_providers_cuda.dll` | مزود CUDA نفسه (~322MB) | إلزامي |

> **ملاحظة تحقق ميداني:** أسماء cuDNN 9 الحقيقية على ويندوز **بلا لاحقة
> `_infer`** (تلك كانت صيغة cuDNN 8) — تحققت من محتوى زيب redistrib الرسمي
> (`cudnn-windows-x86_64-9.12.0.46_cuda12-archive.zip`).

**ملاحظة معمارية مهمة (صُححت بالتجربة الميدانية):** نواة ONNX Runtime مربوطة
ربطاً ثابتاً داخل `HaramLite.exe` (لا يوجد `onnxruntime.dll` منفصل — لهذا حجم
التنفيذي 36MB)، **لكن مزود CUDA يُحمّل ديناميكياً عبر الجسر** (`provider bridge`)
ويحتاج `onnxruntime_providers_shared.dll` + `onnxruntime_providers_cuda.dll`
الحقيقيين (322MB) بالمطابقة الدقيقة (1.22.0) — الافتراض السابق بعدم حاجتهما
كان خاطئاً وأثبتته سجلات `ProviderSharedLibrary::Ensure`. ملفات الـ0 بايت التي
يتركها سكربت البناء بجانب التنفيذي ليست إلا دمى ربط (linker stubs) تُحذف
ذاتياً عند الإقلاع (`ensure_dll_path`) لأنها تحجب النسخ الحقيقية.

**مصدر الملفات عند الرفع:** مستودع NVIDIA الرسمي للتوزيع (cublas/cudnn redist
zip) — يُجمَّع في خطوة CI جديدة في `release.yml` ويُرفع إلى إصدار `assets-v1`
(بجوار ffmpeg/yt-dlp/النموذج). **الإصدارات تُثبَّت قبل الرفع** بمطابقة ما يطلبه
إصدار ORT المضمّن (12.x / cuDNN 9.x) وبتجربة حقيقية على جهاز RTX 3070.

## الشرط 2 — حل مسار القراءة برمجياً (Path Resolution)

المشكلة: ملفات `bin\` مجلد فرعي — Windows لا يبحث فيه افتراضياً عند LoadLibrary.

**الحل (طبقتان، تُنفَّذان معاً):**

1. **`SetDllDirectoryW`** (الأفضل): عند الإقلاع، قبل **أي** تهيئة ORT، يستدعي
   التطبيق واجهة Windows `SetDllDirectory(<مجلد bin>)` — يضيف المجلد لمسار بحث
   DLL الخاص بالعملية الحالية فقط (بلا تلويث بيئة النظام).
2. **حقن PATH احتياطي**: `std::env::set_var("PATH", "<bin>;" + old)` كطبقة ثانية
   (يغطي تحميلات غير مباشرة). يُنفَّذ قبل بدء أي خيط آخر (أول سطر في `run()` وفي
   `cli_entry`) لتفادي سباق الخيوط.

**التوقيت الحرج:** يجب أن يحدث الحقن **قبل** `separator::init_ort_env()` وقبل
أول `MdxSession::load` — سنضع الدالة `cuda_runtime::ensure_dll_path()` كأول
استدعاء في `run()` وفي `cli_entry()`.

**التخزين:** المكتبات تُثبَّت في نفس مجلد `bin` الحالي (بجوار ffmpeg/ffprobe)
عبر معالج الإصلاح الذاتي — فلا حاجة لمسار خاص ثالث.

## الشرط 3 — آلية التراجع الآمن (Fallback بلا انهيار)

مضمونة على ثلاث مستويات:

1. **فشل التنزيل/انقطاع الإنترنت**: معالج الإصلاح ينزّل إلى ملف مؤقت ثم يتحقق
   SHA-256 ثم ينقل ذرياً — أي فشل يترك المكوّن «ناقصاً» دون ملفات نصف مكتملة،
   ورسالة واضحة للمستخدم («تعذر تنزيل مكونات CUDA — سيبقى DirectML نشطاً»).
2. **ملفات تالفة**: التحقق SHA-256 قبل التثبيت + إعادة الفحص عند الإقلاع — أي
   تلف يعيد المكوّن لحالة «ناقص» ويُعاد التنزيل أو يُتجاهل بأمان.
3. **فشل تحميل CUDA وقت التشغيل**: سلسلة التراجع **موجودة ومثبتة** في
   `separator.rs`: محاولة CUDA → فشل؟ → DirectML → فشل؟ → CPU — كل مستوى يمر
   عبر `Result` بلا أي `panic` أو `unwrap`. أُثبتت عملياً اليوم (الجهاز بلا
   cublas: سجلّت الجلسة سقوطاً رشيقاً لـ CPU بدل الانهيار). **سنضيف اختباراً
   آلياً**: طلب جلسة CUDA على جهاز بلا مكتبات → يجب أن تعود `Ok` بجلسة CPU/بديلة
   لا أن تنهار.

> لا يوجد مسار في الكود يستدعي `expect/unwrap` على نتائج ORT — أي فشل محتمل
> يتحول إلى `SepError` يعرضه السجل والواجهة كرسالة، لا كـ crash.

## خطوات التنفيذ — الحالة

1. ✅ `repair.rs`: منفست `cuda-runtime` — نُفذ بنمط **منفست بعيد ذاتي الوصف** (`cuda-runtime-manifest.json` يرفعه CI مع الملفات) بدل بصمات مضمّنة، ليتسنى تحديث المكتبات دون إعادة بناء التطبيق.
2. ✅ `cuda_runtime.rs` (وحدة جديدة): `ensure_dll_path()` (SetDllDirectoryW + حقن PATH) + `is_available()` (فحص الملفات السبعة) + `install()` (تنزيل + SHA-256 + نقل ذري) + `nvidia_gpu_present()`.
3. ✅ `lib.rs`: `ensure_dll_path()` أول سطر في `run()` و`cli_entry()`؛ `cuda_status` تعتمد `cuda_runtime`؛ أمر جديد `install_cuda_runtime` بأحداث `cuda-install`/`cuda-install-done`.
4. ✅ `separator.rs`: بوابة `try_cuda = use_cuda && is_available()` مع تحذير صادق (الشرط 3) + **اختبار التراجع الآلي** `cuda_request_without_runtime_falls_back_gracefully` — يجتاز على جهاز بلا مكتبات (26/26).
5. ✅ `main.ts`: لافتة «سيُنزّل تلقائياً» + تفعيل الخيار يشغّل التنزيل بشريط تقدم + فشل التنزيل يبقي DirectML ويرجع الخيار.
6. ✅ `release.yml`: خطوتا «تجميع CUDA runtime» (redist JSON من NVIDIA + cuDNN zip + توليد المنفست) و«رفع» إلى `assets-v1` مع `--clobber`.
7. ⏳ التحقق النهائي على RTX 3070 (إجراء المالك بعد رفع assets-v1): جلسة CUDA حقيقية + فشل متعمد → تراجع بلا انهيار.

## معايير القبول

- [ ] مستخدم بلا أي NVIDIA: لا يرى أي خيار CUDA — DirectML يعمل فوراً.
- [ ] مستخدم NVIDIA بلا مكتبات: فعّل الخيار → تنزيل تلقائي بشريط تقدم → يعمل CUDA دون أي تثبيت خارجي.
- [ ] قطع الإنترنت أثناء التنزيل → رسالة + DirectML مستمر + لا ملفات تالفة.
- [ ] حذف `cudnn_cnn_infer64_9.dll` يدوياً → التطبيق يعمل بـ DirectML بلا انهيار.
- [ ] اختبار آلي للتراجع يجتاز في CI.
