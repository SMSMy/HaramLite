# مشكلة مزامنة إضافة HaramLite Bridge — مستند تشخيص مستقل

> **الغرض**: هذا ملف مستقل يقف بذاته. من يقرؤه (إنساناً أو نموذجاً) لا يحتاج المستودع ولا سياق المحادثة ليحلّل المشكلة. أرقام الأسطر من `browser-extension/content.js` عند الالتزام `d54050b`.

---

## ١) ما الذي يفعله الامتداد

1. المستخدم يفتح فيديو يوتيوب، فيطلب الامتداد من تطبيق سطح المكتب (عبر native messaging) **صوت المقطع بعد إزالة الموسيقى**.
2. التطبيق يعيد **ملف صوت مقطوع**: مقاطع «الأصوات» فقط (`kept`) — أي أن استراحات الموسيقى (الصمت الناتج عن كتم الموسيقى) **محذوفة من الملف الصوتي**.
3. الامتداد:
   - **يكتم مشغّل الصفحة** (`video.muted = true` ويُثبّته في كل تغيير).
   - يُشغّل الصوت المقطوع في عنصر **`<audio>` منفصل**.
   - **يقفز بالفيديو** فوق المقاطع المحذوفة (`video.currentTime = <بداية المقطع التالي>`)، لأن الصوت لا يحتويها.

⇒ إذن **خطّا الزمن مختلفان**: خطّ الفيديو = الزمن الأصلي الكامل، وخطّ الصوت = الزمن بعد القصّ. والعلاقة بينهما دالة تُسمّى `mapFullToCut`.

## ٢) الرياضيات (الدوال النقية — مُختبَرة في `scripts/check-extension-sync.cjs`)

`kept` = مصفوفة أزواج `[a, b]` بالثواني على **الزمن الأصلي**، للمقاطع المحفوظة (مرتّبة).

```js
// الزمن الأصلي → زمن الصوت المقطوع
function mapFullToCut(t, kept) {
  if (!kept || !kept.length) return t;
  let acc = 0;
  for (const pair of kept) {
    const a = Number(pair[0]), b = Number(pair[1]);
    if (!(b > a)) continue;
    if (t <= a) break;
    acc += Math.min(t, b) - a;
  }
  return acc;
}
// true إذا كان الموضع داخل مقطع محذوف
function isGap(t, kept) { /* false إن كان داخل زوج، وإلا true */ }
// أين يجب أن تقفز الصورة
function skipVideoGaps(t, kept) { /* داخل محفوظ ⇒ t نفسه ؛ داخل فجوة أو قبلها ⇒ بداية المقطع التالي */ }
```

### الثابت الحاسم
`mapFullToCut` **مسطّحة داخل الفجوة**: لكل `t` داخل مقطع محذوف تكون القيمة **نفسها**؛ وإذا كانت الفجوة أمامية (المقطع يبدأ بموسيقى 0→12s، و`kept = [[12, 30]]`) فإن:

```
mapFullToCut(0) = 0    mapFullToCut(0.2) = 0    mapFullToCut(12) = 0    mapFullToCut(20) = 8
```

⇒ **الصوت الممتدّ خطوةً بخطوة لا يحتاج أي تصحيح عند الفجوة**: الموضع الصوتي الصحيح ثابت عبر الفجوة، والصورة وحدها تقفز. **كل «تصحيح» يكتب موضع الصوت إلى الخلف = إعادة سماع صوت سُمِع** ⇒ وهذا هو التكرار المُبلَّغ.

## ٣) المواضع الخمسة التي تُحرّك موضع الصوت (كلها في `content.js`)

| # | السطر | الكود | متى يُنادى | البوابة | يقرأ `video.currentTime`؟ |
|---|---|---|---|---|---|
| ١ | 534 | `try { audio.currentTime = want; }` داخل `reanchorAudio(fullT)` | إعادة إرساء بعد قفزة **يدوية** (‏`w.held`) | داخل `if (w.held)` | **لا** — يأخذ `fullT` المقصود ويُمرّره على `mapFullToCut` |
| ٢ | **539** | `audio.currentTime = audioPos();` داخل `kickAudio()` | عند **كل** حدث `play` للفيديو (‏551) وعند بدء المشاهدة (‏691) | **بلا بوابة** | **نعم** — `audioPos()` = `mapFullToCut(video.currentTime)` |
| ٣ | 573 | `if (Math.abs(audio.currentTime - want) > 0.35) audio.currentTime = want;` | معالج `seeking` | `selfSeek` (نافذة 600ms) | **نعم** |
| ٤ | 614 | `audio.currentTime = audioPos();` | نبضة الانحراف: تحرير احتجاز (`w.held && !video.paused`) | ضمن حالة `held` | **نعم** |
| ٥ | 621 | `if (Math.abs(audio.currentTime - expect) > 0.35) audio.currentTime = expect;` | نبضة الانحراف **كل ثانية** | لا (تسامح 0.35s) | **نعم** |

وفيه أيضاً `audioPos()`:
```js
const audioPos = () => {
  const t = mapFullToCut(video.currentTime || 0, kept);
  return Math.min(Math.max(t, 0), Math.max(audio.duration - 0.05, 0));
};
```

### والكود نفسه يوثّق الخطر — ثم لا يطبّقه على الأربعة
تعليق `reanchorAudio` (الأسطر 516-520) يقول بالحرف:

> «الهدف يُحسب من الهدف المقصود لا من `video.currentTime`، لأن **قراءته بعد الإسناد غير موثوقة (القفز غير متزامن)**.»

⇒ أي أن المشروع **يعرف** أن `video.currentTime` لا يُقرأ بعد قفزة — لكن `reanchorAudio` وحدها هي التي تأخذ الزمن المقصود. **المواضع ٢ و٣ و٤ و٥ كلها تحسب من `video.currentTime`**، ومنها موضعان قد يعملان **بعد قفزتنا مباشرة**:
- **الموضع ٢ (`kickAudio`)**: قفزتنا إسنادٌ لـ`currentTime`، ومشغّل يوتيوب كثيراً ما يُطلق `play`/`playing` حول القفزات. فإن أُطلق و`video.currentTime` **لم يستقرّ بعد على القيمة الجديدة**، فإن `audioPos()` تُرجع موضعاً **أقدم** ⇒ **سحب الصوت للخلف بمقدار تأخّر الإبلاغ** (قد يكون مئات الأجزاء من الثانية = كلمة كاملة).
- **الموضع ٥**: المُصحّح الدوري بتسامح **0.35s متماثل**؛ والخطأ **غير متماثل**: تقدّم الصوت (أمام) لا يُسمع تقريباً (يكفي وقفة قصيرة)، أما **السحب للخلف فيُسمع تكراراً**. فالمُصحّح اليوم يعالج الحالتين بعنف واحد.

## ٥) فرضيات مرتبة (كلها قابلة للدحض بقياس واحد)

**ف١ (الأقوى): `kickAudio` تُعيد الإرساء من قيمة `video.currentTime` قديمة عند حدث `play` تابع لقفزتنا.**
- التنبؤ: في أثر (trace) يظهر `video.currentTime` وقد **عاد للخلف** (قيمة داخل الفجوة) في اللحظة نفسها التي كُتب فيها `audio.currentTime` من الموضع ٢ ⇒ ثم يستقرّ `video.currentTime` على قيمة القفزة.
- الاختبار الحاسم: تسجيل الموضعين كل 20-50ms حول لحظة التكرار، مع **مَن كتب** ولماذا.

**ف٢: المُصحّح الدوري (الموضع ٥) يسحب الصوت للخلف بتسامح 0.35s عند التقدّم المتراكم.**
- التنبؤ: الكتابة تحدث عند نبضة الثانية (‏1000ms) لا عند حدّ فجوة، وبفرق ‏≈0.35s أو أكبر.
- لو صحّ: العلاج ليس «تشديد التسامح» بل **معالجة غير متناظرة**: عند تقدّم الصوت ⇒ **توقف قصير** (‏`audio.pause()` لعشرات الأجزاء ثم `play`) بدل السحب للخلف، أو تصحيح ناعم بـ`playbackRate` مؤقتاً.

**ف٣: نافذة `selfSeek` (600ms) أقصر من تأخّر الحدث عند مشغّل بطيء/ثقيل، فيمرّ `seeking` غير موسوم.**
- التنبؤ: كتابة من الموضع ٣ بعد أكثر من 600ms من آخر `w.selfSeek`.

**ف٤: التطبيق يُبلّغ `kept` على **مسار الأصوات** بينما الصوت المُسلَّم قد يكون مقطوعاً بحدود مختلفة (اختلاف هوامش القص) ⇒ انزياح ثابت بين الخريطة والملف.**
- التنبؤ: مجموع `kept` ≠ مدة ملف الصوت المُسلَّم بفرق أكبر من إطار واحد، أو انزياح **ثابت** لا يتراكم.
- الاختبار: مقارنة `sum(b−a)` مع `audio.duration` لحظة التحميل، وتسجيل الفرق.

## ٦) القياس المطلوب (وأستطيع إضافته الآن)

لا يمكن الحكم بين الفرضيات بلا **أثر زمني**. الإضافة المقترحة (معطّلة افتراضياً، تُفتح بـ`localStorage['hl.synclog']='1'`):

```js
const slog = (() => { try { return localStorage.getItem('hl.synclog') === '1'; } catch { return false; } })();
const trace = (site, extra) => {
  if (!slog) return;
  const row = {
    t: Date.now() % 60000, site, v: +video.currentTime.toFixed(3),
    a: +audio.currentTime.toFixed(3), want: +audioPos().toFixed(3),
    gap: isGap(video.currentTime, kept), held: w.held, drift: extra || '',
  };
  (window.__hlSync = window.__hlSync || []).push(row);
  if (window.__hlSync.length > 4000) window.__hlSync.shift();
  console.log('HL-SYNC', JSON.stringify(row));
};
```
تُنادى في: المواضع الخمسة قبل/بعد الكتابة · `gapTick` عند القفز · كل حدث `play/seeking/seeked/pause` · وكل نبضة انحراف.
والمُخرَج المطلوب من تجربة واحدة: الأسطر التي فيها **`a` تنقص** (سحب للخلف) + قيمة `site` التي كتبت + هل كان `gap` صحيحاً في تلك اللحظة.

## ٧) أسئلة للمراجع
1. هل يوجد مسار سحبٍ للخلف لم أُحصِه؟ (الجدول في §٣ يُدّعي الحصر.)
2. هل الصواب أن يكون **مصدر الحقيقة** هو `audio.currentTime` المُتقدّم خطوةً بخطوة (والفيديو تابعاً له) بدل العكس؟ أي: عند كل حدّ فجوة، **قِس** الموضع الصوتي الفعلي واشتقّ منه موضع الصورة، بدل اشتقاق الموضع الصوتي من `video.currentTime`.
3. هل الأصح معمارياً أن يُسلَّم **زمن كل مقطع** من التطبيق (لا الخريطة فقط) وأن يُبنى ملف صوت **بفجوات صامتة بطولها الأصلي** (فيصير خطّا الزمن متطابقين والمسألة تصبح `mute` فقط بلا قفز ولا خريطة)؟ هذا يلغي الصنف كله من الأعطال، وثمنه حجم الملف.

## ٨) حدود هذا المستند
- لا اختبار متصفّح في هذه البيئة: كل ما سبق مبنيّ على قراءة الكود وعلى بلاغات المالك، لا على أثر تنفيذي.
- الأعراض الثلاثة موصوفة بكلمات المالك: (١) «الصوت ينتقل إلى 12.2s ثم يعود لوضعه الصحيح، يلتقط (نعم) ثم يعيد (نعم هناك رجل)» · (٢) «إذا كان متكرراً يكرر الكلمة إلى ثلاث مرات، وإذا تباعدت التخطيات يتقدم الصوت على الصورة ويصحح نفسه بعد فترات» · (٣) «لا تزال مشكلة الصمت المتكرر تُعيد الكلمات».
