> **حالة المستند**: خطة للاعتماد. **لا يُنفَّذ منها سطر قبل موافقة المالك.**
> **الأساس**: قياسات 0.2.5 وبلاغات المالك الميدانية (2026-09-15) وتدقيق الإضافة في `docs/AUDIT.md` والمستند المستقل `docs/EXT-SYNC-BRIEF.md`.

## ١) الطلب (المالك، حرفياً)
> «سنحدث ذلك ليصبح أسلس بصرياً فنستخدم القطع والتسريع معاً حتى نطور تجربة المشاهدة. المشاهد القريبة المتقاربة تستخدم التسريع والمتباعدة تستخدم القطع.»

أي: **لم يعد التخطي خياراً واحداً**، بل قرارٌ لكل فجوة: تُسرَّع (fast-forward) أو تُقطع (قفزة).

## ٢) لماذا هذا ممكن عندنا بأقل كلفة من مصدر الإلهام — وهذه أهم نقطة في الخطة
| | عندهم (Jump Cutter) | عندنا |
|---|---|---|
| ما يُسرَّع | **العنصر الوسائطي كله** (صوت + صورة) لأن صوتهم هو صوت الفيديو نفسه | **الصورة وحدها**: `video.playbackRate` على مشغّل الصفحة |
| أثر التسريع على الصوت | يغيّر طبقة الصوت ⇒ يحتاج حفظ طبقة، ويعترف المستند بـ«تشويه صوتي وتأخير»، وله خيار `enableDesyncCorrection` لتصحيح فكّ التزامن | **صفر**: الصوت المُسلَّم **لا يحتوي الفجوة** (مقطوع من التطبيق) ⇒ يُحتجَز أثناءها ثم يستأنف من موضعه المخطَّط |
| اعتماد على الخريطة | لا | نعم: `mapFullToCut` **مسطّحة داخل الفجوة** ⇒ موضع الصوت عند نهاية الفجوة = موضعه عند بدايتها ⇒ **لا انزياح يولده التسريع إطلاقاً** |

⇒ «التسريع» عندنا = **احتضار الصوت (pause) + رفع معدّل الصورة** ثم إعادتهما. لا سحب للصوت، ولا تغيير طبقة، ولا `playbackRate` على الصوت.

**ومكسب مؤكَّد من تشخيصنا اليوم**: القفزة تُنتج `seek` ⇒ يُعيد يوتيوب التخزين ⇒ **وقفة صورة** ⇒ تقدّم صوت («الفيديو قد يقف قليلاً بعد التخطي» — بلاغ المالك). **والتسريع لا يُنتج `seek` إطلاقاً** ⇒ لا وقفة ولا تقدّم. أي أن التسريع **أكثر أماناً للمزامنة** لا أسلوباً جمالياً فقط.

## ٣) القرار: دالة نقية لكل فجوة
```js
// تُحسب من الخريطة وحدها — قابلة للاختبار في الحارس بلا متصفّح.
// gap        : طول الفجوة بالثواني
// keptBefore : طول المقطع المحفوظ الذي سبقها (منذ نهاية الفجوة السابقة)
// keptAfter  : طول المقطع المحفوظ الذي يليها
// cfg        : العتبات أدناه
function planGap({ gap, keptBefore, keptAfter }, cfg) {
  // ١) فجوة قصيرة جداً: قفزة غير محسوسة، والتسريع لا يوفّر شيئاً يُذكر.
  if (gap < cfg.cutBelow) return { mode: 'cut', reason: 'tiny' };
  // ٢) فجوة معزولة: ما قبلها وما بعدها طويلان ⇒ قفزة واحدة نظيفة وتوفير أقصى.
  if (keptBefore >= cfg.isolated && keptAfter >= cfg.isolated) return { mode: 'cut', reason: 'isolated' };
  // ٣) فجوة طويلة: تسريعها يعني مشاهدة تسريع طويل ⇒ القطع أرحم.
  if (gap > cfg.maxSpeedGap) return { mode: 'cut', reason: 'long' };
  // ٤) وإلا: تسريع بمعدّل ثابت، مع سقف زمن مشاهدة.
  const rate = Math.min(cfg.rate, Math.max(1.2, gap / cfg.targetDwell));
  if (gap / rate > cfg.maxDwell) return { mode: 'cut', reason: 'dwell' };
  return { mode: 'speed', rate: +rate.toFixed(2) };
}
```
**العتبات المقترحة مبدئياً — وكل رقم منها مُعلَن أنه يحتاج قياساً قبل التثبيت**:

| الرمز | القيمة المقترحة | أساسها الحالي | ما يقيسها |
|---|---|---|---|
| `cutBelow` | **0.6s** | قفزة أقصر من ذلك لا تُلاحظ بصرياً | طول أصغر فجوة فعلية (‏Rust: 500ms حدّ أدنى) |
| `isolated` | **20s** | مقطع محفوظ 20s يعني أن الفجوة «حدث نادر» فالقفزة مقبولة | توزيع أطوال المقاطع المحفوظة |
| `maxSpeedGap` | **6s** | تسريع 6s عند 3× = ثانيتان مشاهدة | توزيع أطوال الفجوات |
| `targetDwell` | **1.0s** | أقصى زمن مشاهدة مستهدف لفجوة تُسرَّع | ذوق المالك + القياس |
| `rate` (سقف) | **3.0×** | فوقه يتلاشى المحتوى بصرياً | قياس انسيابية الصورة |
| `maxDwell` | **1.5s** | شبكة أمان: إن تجاوز التسريع هذا الزمن ⇒ اقطع | ذوق المالك |

**القياس قبل التثبيت (إلزامي)**: توسيع `gapStats` إلى **مدرّج** (عدد الفجوات في نطاقات 0.5–1 · 1–2 · 2–4 · 4–8 · >8 ثوان) + **طول المقطع المحفوظ قبل كل فجوة** (وسيط وأدنى). يُطبع في سطر `load` الموجود. ثم تُختار العتبات من **بيانات مقاطع حقيقية عند المالك** لا من ذوق.

## ٤) آلة الحالة الدقيقة
الحالة الجديدة: `w.pace = null | { boundary, landing, rate }`.

| الحدث | الحالة الحالية | ما يحدث في الخطة |
|---|---|---|
| ماسح الفجوات (250ms، :807-813) يجد `nextGapStart` | يُسلّح مؤقّتاً عند الحدّ (`w.gapTimer`) | يقرأ `planGap` **مرة واحدة عند التسليح** ويخزّن القرار في `w.pace` (وإن كان داخل فجوة أصلاً ⇒ `gapTick()` فوري كما اليوم :807) |
| بلوغ الحدّ (`gapTick`) | يقفز إلى `landing` | **إن `cut`** ⇒ كما اليوم (قفزة + `selfSeek`) · **إن `speed`** ⇒ `audio.pause()` + `w.held = true` + `video.playbackRate = rate` + وسم `w.selfRate` + مؤقّت خروج عند `(landing − video.currentTime)/rate` |
| خروج التسريع | — | `video.playbackRate = 1` + `w.selfRate = null` + `setAudioTime('pace-release', audioPos(), true)` (‏`allowBack=true` كحالة الاحتجاز) + `audio.play()` + `w.held = false` |
| شبكة أمان للخروج | — | كل نبضة 250ms: إن لم يبقَ داخل فجوة (`!isGap`) ⇒ اخرج فوراً |
| نبضة الانحراف (1s) | تُصحّح | **تتجاهل `w.pace`** كما تتجاهل `w.stalled` (الصوت محتجَز ⇒ لا تصحيح) |
| احتجاز التجمّد (`waiting`) | يوقف الصوت | يُبقى كما هو، **وإن وقع داخل تسريع** ⇒ يوقف الصوت فقط ولا يمسّ المعدّل |
| `seeking` من المستخدم | يُعيد الإرساء | **يُخرج من التسريع** (المستخدم طلب موضعاً) ثم السلوك القائم |
| `pause` | يوقف الصوت | يُخرج من التسريع أيضاً (لا تسريع بلا تشغيل) |
| نهاية المشاهدة `stopWatch` (:824) | تُعيد `w.prevRate` (:837) و`pinPlayerRateRestore` (:845) | يُضاف إليها مسح `w.pace` ومؤقّت الخروج فقط — **إعادة المعدّل قائمة أصلاً فلا تُكرَّر** |

**نقطة دقيقة وخطيرة**: `w.prevRate` يُلتقط عند بدء المراقبة (:532) و‏`stopWatch` تستعيده (:837). ⇒ **لا نلمس `w.prevRate` عند دخول التسريع**: لو كتبنا فيه معدّل التسريع (2.5×) لصار معدّل الاستعادة بعد كل توقّف 2.5× **دائماً** — عيب دائم صامت. وعند الخروج من التسريع نُعيد `w.prevRate` كما تفعل `stopWatch` ⇒ **نُعيد استخدام الآلة القائمة ولا نضيف آلة ثانية**.

**وفي `ratechange`** (وهو اليوم يفرض 1× دائماً): يصير
```js
on(video, 'ratechange', () => {
  if (w.selfRate && Math.abs(video.playbackRate - w.selfRate) < 0.05) { trace('rate', 'ours'); return; }
  // الموقع أعاد المعدّل ⇒ التسريع غير مدعوم هنا ⇒ ارجع للقطع لهذه الفجوة
  if (w.pace) { trace('rate', 'rejected→cut'); w.pace = null; gapTick(w.paceBoundary, w.paceLanding); }
  if (video.playbackRate !== 1) { try { video.playbackRate = 1; } catch {} }
  pinPlayerRate(); audio.playbackRate = 1;
});
```
⇒ **سقوط آمن مُختبَر**: إن عاد الموقع إلى 1× نعود إلى القطع في تلك الفجوة، بلا تعليق تسريع.

## ٥) الأثر والحرّاس (بنفس صرامة الجولات السابقة)
**الأثر** (معطّل افتراضياً `hl.synclog`): صفوف جديدة — `pace-plan` (‏`mode` · `rate` · `gap` · `keptBefore` · `reason`) · `pace-enter` · `pace-exit` · `pace-reject` · و`rate: ours/rejected`. **والثابت الذي نحرسه**: لا صفّ فيه `d=` سالب خارج `stall-release` و`held-release` و`pace-release` و`seeking` و`drift-confirmed`.

**فحوص الحارس الجديدة** (تُضاف إلى `scripts/check-extension-sync.cjs`، ولكلٍّ **مُفسَد**):
1. `planGap` دالة نقية تُستخرج ويُختبر قرارها على ≥ 8 حالات (قصيرة · معزولة · طويلة · متقاربة · على الحدود تماماً).
2. كتابات موضع الصوت تبقى **اثنتين** (`setAudioTime` · `reanchorAudio`) — التسريع **لا يكتب للصوت** إلا عبر البوابة عند الخروج.
3. `gapTick` في وضع `speed` **لا يقفز** (`video.currentTime` لا يُكتب في هذا الفرع) — بفحص احتواء داخلي.
4. `pace-release` يُنادى بـ`allowBack=true` حصراً، والنبضة تتجاهل `w.pace`.
5. **لا كتابة على `w.prevRate`** في مسار التسريع كلّه (‏أعلى خطر في الخطة: معدّل استعادة دائم 2.5×) مع بقاء `stopWatch` مُعيدةً له (:837).
6. `ratechange` يميّز معدّلنا (`selfRate`) ويسقط إلى `cut` عند الرفض.
7. `audio.playbackRate` **لا يُسنَد إليه إلا `1`** (اليوم :683 و:701) — يُحرس سلبياً: صفر إسناد بقيمة ≠ 1.

## ٦) معايير القبول
1. **آلياً**: `node --check` · الحارس (الفحوص الحالية 89 + الجديدة) كلها خضراء · الحزمة تُبنى 1.1.5 (أو 1.1.4 إن لم تُرفع بعد).
2. **ميدانياً (المالك)**: على مقطع فيه فجوات متقاربة: **لا قفزات متلاحقة مرئية** بل تسريع سلس، ولا تكرار كلمة، ولا تقدّم صوت.
3. **ميدانياً**: على مقطع فيه فجوة معزولة طويلة: قفزة واحدة كما اليوم.
4. **الأثر دليل**: صفوف `pace-plan` تُظهر `mode` مختلفاً للحالتين، و`pace-reject` **غائب** (أي أن الموقع قبل التسريع).
5. **المزامنة**: صفر `drift-confirmed` وصفر `stall hold` (لأن التسريع لا يُنتج `seek`).

| الخطر | الاحتمال | الخفّض |
|---|---|---|
| يوتيوب يعيد `playbackRate` إلى 1× (سياسة مشغّله) | **متوسط** | `selfRate` + كشف `ratechange` + **سقوط إلى القطع** فوراً + وسم في الأثر |
| كتابة معدّل التسريع في `w.prevRate` ⇒ استعادة دائمة بمعدّل مسرَّع بعد كل توقّف | **متوسط** | حارس صريح (بند ٥-٥) + استعادة `w.prevRate` القائمة (:837 · :845) |
| صوت يبقى محتجَزاً بلا خروج (فجوة بلا نهاية/خريطة شاذّة) | منخفض | شبكة أمان كل نبضة: إن لم يبقَ داخل فجوة ⇒ اخرج |
| تقطيع الصورة عند تغيير المعدّل (إطار مسقَط) | منخفض | قياس: تُسجَّل مدة التسريع و`dropped` غير متاح ⇒ الحكم بالعين |
| تسريع يقلّل التوفير الزمني (10s عند 3× = 3.3s مشاهدة) | متوسط | `maxSpeedGap` + `maxDwell` يقطعان ما طال |
| **نقل كود من مصدر AGPL** | ممنوع | **لا سطر يُنسخ**؛ القرار دالتنا، والأسماء للتعريف فقط |

## ٨) واجهة المستخدم (قرار للمالك)
الخيار الحالي في قائمة الزر الأيمن ثنائي (تخطي/بلا تخطي) ويُخزَّن في `hl.skipgaps` (`'1'`/`'0'`). المقترح: **ثلاث حالات**:
`off` (بلا تخطٍّ كما اليوم) · `hybrid` (تسريع القريب وقطع المتباعد — **الافتراضي الجديد**) · `cut` (القطع دائماً — سلوك اليوم).
**هجرة القيمة المخزَّنة**: `'1'` ⇒ `hybrid` · `'0'` ⇒ `off` (‏`'0'` ليس `'cut'` كي لا يتغيّر سلوك من أطفأ الميزة). ومفاتيح ترجمة جديدة في الجدولين (‏`ar`/`en`) بنفس البنية.

## ٩) ما لا يشمله هذا المستند (حدود صريحة)
- **لا تمديد زمني للصوت** ولا حفظ طبقة (لا حاجة: الصوت لا يحتوي الفجوة).
- **لا تغيير في التطبيق (Rust)**: لا مساس بـ`SilenceConfig` (‏`min_silence_ms=800` · `keep_ms=150`) ولا بخط التسليم. الخطة **داخل الإضافة وحدها**.
- **لا عتبات بالذوق**: كل رقم في §٣ يُثبَّت بعد قياس المدرّج، وإن لم يُقس يُعلَن أنه غير مقيس.
- **لا قرار على «مصدر الحقيقة»** (‏§٧-٢ في المستند المستقل): يبقى `video.currentTime` مصدر الإسناد، والصوت محتجَز أثناء التسريع.
- **لا مسّ لمحرّك الفصل ولا للموقع ولا لسير العمل.**

## ١١) أسئلة للمالك قبل التنفيذ
1. **العتبات**: أقبل بالمقترح المبدئي (‏§٣) للتجربة الأولى، أم تريد تجربة **قياس فقط** أولاً (خطوة ١) ثم نُثبّت الأرقام من بيانات مقاطعك؟
2. **الافتراضي**: `hybrid` افتراضياً لكل مستخدم جديد — أم يبقى `cut` افتراضياً ويتغيّر بيد المستخدم؟
3. **حدّ التسريع**: هل 3× سقف مقبول بصرياً عندك، أم 2×؟ (يُقاس بالعين على مقطع حقيقي).
4. **الفجوة الطويلة**: تُقطع دائماً (رأيي) أم تُسرَّع إن كانت معزولة حتى 8s؟
